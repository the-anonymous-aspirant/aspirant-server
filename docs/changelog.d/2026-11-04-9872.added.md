- **PayPal import reads Excel files** (system_3 #9862-A1). `POST
  /invoicing/payments/import` now takes a PayPal activity export as .xlsx as
  well as CSV. The format is read from the file's bytes, not its name. Both
  go through one header-by-name parser. In the Excel file, date serials
  (1900 and 1904 systems) become dates and amounts are rounded to cents. The
  reader uses the standard library only and caps the zip's entry count
  (256), the bytes each part unpacks to (32 MB), shared texts (100k), rows
  (20k) and columns (200). A legacy .xls is refused with a message to save
  it as .xlsx or CSV. The summary gains `format` and `refunds`.
- **Reversed rows no longer import** (system_3 #9862-A1). The classifier
  follows the Type strings of a real PayPal statement. A reversal ("Reversal
  of ACH Withdrawal Transaction", "Payment Reversal") is skipped, and so is
  the row it reverses: the same transaction id or the reversal's reference,
  moving the same amount the other way. Before, a bounced withdrawal
  imported as a phantom bank deposit or as a phantom incoming payment. An
  incoming "Payment Refund" imports with category `refund` instead of
  `uncategorised`.

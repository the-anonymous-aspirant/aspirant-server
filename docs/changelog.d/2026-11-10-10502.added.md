- Nightly per-service usage rollup (system_3 #10490-C / #10502). Once daily
  near 03:00 UTC, `service_usage_rollups` gets one row per aspirant-monitor
  container (memory/disk, plus proxied-call counts over a trailing 30 days
  for the upstreams that map to it) and one row per server-native feature
  table (`#10490-B`'s audit: whole-table `count(*)` and last-used timestamp).
  Every usage figure is a pointer — `nil` means "no signal for this row's
  kind", never a false `0`. No new cross-service database credential or
  docker-socket-proxy allowlist entry: this reuses aspirant-server's own
  database and the existing `monitorClient` proxy seam (`#10490-A1`).

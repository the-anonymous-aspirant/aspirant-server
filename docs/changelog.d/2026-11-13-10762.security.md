- **Purge refuses a payment on an issued invoice** (system_3 #10647-A1,
  security c66061). `POST /invoicing/payments/purge` and
  `/invoicing/payments/:id/purge` now refuse with 409 `payment_on_invoice`
  when an issued invoice still lists a removed payment, alone or anywhere in a
  batch, and write nothing. No path creates that state today: draft create,
  draft edit and issue all refuse a removed payment. But purge is the one step
  that cannot be undone and it deletes link rows, so it no longer trusts that
  guard. The legacy `DELETE /invoicing/payments/:id` already checked this.
  Remove and purge now share one refusal and its wording.

`POST /api/system/containers/:name/start|stop` now answers `502` with code `monitor_auth_failed` when the monitor refuses the server's control token (a monitor 401, or a 403 other than `not_controllable`), instead of passing the 401 through (system_3 #10641). The client read a passed-through 401 as an expired session and logged the admin out mid-click. Now System health shows "The monitor refused the server's credentials." The container-control log still records the monitor's own status. Every other monitor answer passes through unchanged.

- **Invoicing: harden the work-expenses endpoints added in #10416** (system_3
  #10431, security review of PR 175, c63859 on #10429). `lockExpenseRow` is
  now scoped to the owner, not keyed on the expense id alone. Seeding an
  owner's starter categories on `GET /api/invoicing/expense-categories` and
  `GET /api/invoicing/expenses?category=` now takes the book lock first, so
  two concurrent first requests cannot both race the `(owner, name)` unique
  index. `POST /api/invoicing/expense-categories` now records an audit event
  like every other invoicing write. A test now pins the owner filter on the
  category-validity check itself (previously only the expense and category
  *rows* were isolation-tested, not the check a create runs against them).

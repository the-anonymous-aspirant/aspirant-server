- **Generate invoices: one draft per paid-work payment** (system_3 #11504,
  epic #11497). `POST /api/invoicing/invoices/generate` takes exactly one of
  `{"month":"YYYY-MM"}` or `{"payment_ids":[…]}` and creates one draft for
  each payment, prefilled as Create invoice prefills it (client, payment date,
  one line with the note and the amount). A payment an invoice already covers,
  draft or issued, is not drafted again and comes back under `skipped` with
  that invoice, so a second press adds nothing; a cancelled invoice does not
  count. Nothing is issued and no number is drawn: accepting a draft is still
  `POST /invoices/:id/issue`, rejecting it `DELETE /invoices/:id`. The call
  only adds rows in the caller's own book and changes no existing payment,
  client or invoice.

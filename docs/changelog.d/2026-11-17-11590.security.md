- **Deleting a user is refused while the user still has an invoicing book**
  (system_3 #11590, from the operator's answer on #11380). `DELETE
  /data_models/users/:id` now answers 409, "This user still has invoicing
  records, which must be exported and removed before the account can be
  deleted", and removes nothing, when the user owns a row in any of ten
  tables: the profile and its logo, clients, invoices, payments, expenses,
  expense receipts, failed imports, the Book's selection and its presets.
  Issued invoices have a legal retention period, so a book is never removed as
  a side effect of removing its owner, and there is no path that removes one.
  Three kinds of row are not a book and go with the account instead: expense
  categories (the defaults are seeded by reads) and the two tombstone tables.
  Audit events neither refuse a delete nor are touched by one.

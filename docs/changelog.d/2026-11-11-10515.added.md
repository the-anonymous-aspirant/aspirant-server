- New admin-gated endpoints for the per-service admin page (system_3
  #10491-B): `GET /admin/system/service-usage` reads the latest
  `service_usage_rollups` run directly (this service's own table, no new
  credential); `POST /admin/system/containers/:name/start` and `/stop` proxy
  to aspirant-monitor's write-scoped container control (`#10514`), carrying a
  new `MONITOR_CONTROL_TOKEN` bearer credential. The admin-tier gate on this
  route group is the only way a client reaches either proxy route; the
  monitor's own bearer token and hard container-name allowlist are a second,
  independent check once the call arrives — at no point does the client hold
  a credential that talks to Docker directly.

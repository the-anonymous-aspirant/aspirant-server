- **"Add payers": rows of one new name make one client** (system_3
  #12319). `POST /invoicing/payers` no longer refuses two rows whose
  `new_client_name` is the same name (§3.142 Decision 4). It creates one
  client, named as the first such row typed it, and links every row's
  payments to it. The first row gives the PayPal email and IBAN; a later row
  fills only one still empty, under the usual "not when another client has
  it" rule. A row with the new optional `"second_client": true` is a client
  of its own, for two people of one name. A new name equal to a client
  already in the book still answers 409 `client_exists`.

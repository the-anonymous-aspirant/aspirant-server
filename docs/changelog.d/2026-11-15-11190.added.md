- **Remembered form values** (system_3 #11190, design_conventions §3.154).
  `GET`, `PUT` and `DELETE /users/me/form-values/{tool}` store one record per
  user per tool, for the signed-in user only: no path, query or body field can
  name a user. Tools are a server-side allowlist with a tier each. The first is
  the rent-receipt tool, `kvitto`, at admin tier. An unknown tool is a 404.
  Each tool accepts a fixed set of keys (for `kvitto`: address,
  monthly_amount, recipient and payer, each text with a length cap), and any
  other key is refused. A refusal names the field, never its value, and no
  value reaches a log. Every response carries `Cache-Control: no-store`.
  `DELETE` removes the row. Deleting a user removes their records too, inside
  `User.DeleteUser`, because a user delete is a soft delete and a foreign-key
  cascade would never fire.

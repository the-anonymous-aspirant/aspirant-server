- **Invoices: an N26 payment prints how it was paid, and no made-up id**
  (system_3 #12257). An issued invoice over a payment imported from an N26
  statement or CSV export read "per n26 (Transaktions-ID: csv-…)". N26 rows
  carry no transaction id, so the import derives one to recognise a
  re-upload, and that key was printed as if the bank had issued it. The line
  now reads "Zahlung erhalten am … per Banküberweisung". An N26 transfer
  confirmation's operation id is the bank's own and still prints, as PayPal
  and Stripe ids do. A payment whose method is not known ends at the date,
  rather than printing its source's name. The invoices CSV leaves a derived
  id out of "Transaktions-IDs". Payments and expenses gain `shown_reference`:
  the owner's own reference for a hand entry, the provider's id for an
  import, or empty when the server made the id up. `reference` and
  `transaction_id` are unchanged, and invoices already issued are not
  rewritten.

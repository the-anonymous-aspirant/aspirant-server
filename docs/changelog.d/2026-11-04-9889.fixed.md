- **A transfer from PayPal into N26 can no longer be invoiced a second time**
  (system_3 #9889, from #9881). Money that reaches the N26 account from
  PayPal is the owner's own withdrawal, already held by the PayPal import.
  The N26 parse now leaves out a credit whose sender name contains "PayPal"
  (her confirmations print `PAYPAL`) and counts it under the file as
  `skipped: {"paypal_transfer": n}`. Confirm refuses such a row with
  `invalid_row`. An N26 row from PayPal stored before this fix can no
  longer be set to `paid_work` (`paypal_transfer_not_paid_work`) and cannot
  go on a draft or be issued (`payment_paypal_transfer`); any other category
  stays allowed, so it can be moved off paid work. The note is not read, so
  a customer's own transfer that mentions PayPal stays a payment.

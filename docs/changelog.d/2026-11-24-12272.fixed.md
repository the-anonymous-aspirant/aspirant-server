- **Invoices: the number prefix's hyphens are checked, and its case is one
  series** (system_3 #12272).
  - **Before:** a prefix of `2026-` issued `2026--001`, since the app adds a
    hyphen before the number. And changing `r` to `R` started a second series
    at 1, so a book could hold both `r-001` and `R-001`.
  - **Saving the profile (`PUT /invoicing/profile`):** a new or changed
    prefix is refused with 400 when it ends with a hyphen
    (`prefix_ends_with_hyphen`), starts with one
    (`prefix_starts_with_hyphen`), or holds two in a row
    (`prefix_double_hyphen`). A prefix the Save does not change is not
    checked, so a profile stored with `2026-` keeps saving its other fields.
  - **Case:** the next number is read across prefixes that differ only in
    capital letters. Changing `r` to `R` after `r-002` continues at `R-003`:
    the save keeps the server's next number, 3, whatever number is sent, as
    for any prefix in use (system_3 #12306).
  - **The check before export (`/invoicing/validation`):** each prefix's
    series is still checked exactly, but a number another case of the prefix
    holds is no gap. A book that already holds the same number under two
    cases (`r-001` and `R-001`) is not rewritten: it reads one warning,
    `number_case_twin`, "Invoices R-001 and r-001 have the same number; their
    prefixes differ only in capital letters.", and still exports.

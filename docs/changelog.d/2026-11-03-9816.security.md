- **The server container runs as a non-root user** (system_3 #9816, from the
  security review of #9812). The runtime stage adds uid/gid 1000 ("server"),
  moves the working directory from /root to /app (asset_mappings.json is
  saved to the working directory, which must stay writable), chowns the
  image-layer /data/files, and sets USER before CMD. The bind-mounted
  /data/aspirant/files is already owned by host uid 1000, so deployed
  writes are unchanged.

- **Invoicing: four kinds of bad request answer a refusal, not 500**
  (system_3 #12268).
  - An id of 2^31 or more names no row: the keys are 32-bit columns.
    Wherever such an id appears, it now answers what an unknown id answers
    in the same place:
    - in a path, 404;
    - in `?entity_id=` and `?client_id=`, an empty list;
    - in a body or in the merged PDF's `?ids=`, that field's existing
      refusal.
  - `next_invoice_number` on the profile has a ceiling of 2147483647, with
    a 400 above it. Issuing with the counter at that value answers 422
    `invoice_numbers_exhausted`; the draft stays a draft and no number is
    used.
  - A NUL character in a client's or the profile's text fields answers
    400. A NUL in a PayPal CSV cell is dropped, as the N26 CSV parser
    drops it.
  - A receipt upload or removal takes the book lock first. Two first
    uploads on one expense now run one after the other, and the second
    replaces the first.
  - The merged PDF's lookup failure no longer carries the database
    driver's text.

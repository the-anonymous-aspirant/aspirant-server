- **An expense category ze added can be removed and restored, and one typed
  into an expense is saved with it** (system_3 #11579, #11497 item 19; design
  §3.161, until it merges #11566; the operator's c71346 on #10985).
  `POST /invoicing/expense-categories/:id/remove` and `/:id/restore` mark one
  of zir own categories removed or live again, and each writes one audit
  event. A removed category is kept: every expense that has it keeps it, and
  the Book, its selection, presets and the CSV count it as before. Only
  choosing it for an expense that does not already have it is refused
  (`removed_category`), on create, edit and both import confirms. The ten
  starters and Private are refused (`builtin_category`). The category list
  now carries `removed_at` and `builtin`. An expense create or edit may send
  `"create_category": true` with a typed `category`: a live name, in any
  case, is used; a removed one is restored; otherwise a category counting as
  Other is made, in the same transaction, so a refused name or a refused
  expense saves neither. `POST /invoicing/expense-categories` with a removed
  name restores it as it was (200) instead of answering duplicate. The new
  `removed_at` column is nullable; no existing category or expense changes.

- **A new confirmation link on request** (system_3 #11143 / #11391; cleared by
  security c70050). `POST /verify-email/resend {email}` mails a new link to an
  account whose address was never confirmed. Before this nothing on the site
  could, so an account whose link was spent, expired or cut short could never
  sign in.
  - **No oracle.** Every outcome that depends on the users table returns one
    constant: unknown address, already confirmed, waiting, or failed lookup.
    The answer is the same in time as well as in bytes: the token and the mail
    are made after the response by a new shared `deliverLater`, so no answer
    waits on SMTP. #11393 moves `/password/forgot` and `/signup` onto it.
  - **Limits.** It sits behind `PublicAuthRateLimit("email")`: per IP, and per
    recipient on the lower-cased, trimmed address. The lookup normalises the
    same way, and mail goes to the stored address only.
  - **Closed site.** A closed site, or one with no relay, refuses as `/signup`
    does.
  - **Logs.** No address reaches a log line: relay errors are redacted.
  - **Older links.** An older confirmation link keeps working.
